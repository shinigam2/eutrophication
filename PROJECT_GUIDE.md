# Полная карта проекта: путь данных через все 4 части (`PROJECT_GUIDE.md`)

Этот файл — **главный «живой учебник» по нашему командному проекту**. Он создаётся и обновляется по мере разработки, чтобы **каждый из 4 участников** видел всю картину целиком:
- откуда именно берутся сырые данные;
- через какие файлы кода и формулы они проходят;
- как выглядят промежуточные и итоговые таблицы;
- как работают оба режима — **Спутниковый** и **Лабораторный**;
- как результат попадает в модели, базу знаний и на экран пользователю.

---

### 1.3. Через какие формулы прогоняются данные (сводка)
*(Подробные математические доказательства и примеры расчёта — в [`DECISIONS.md`](DECISIONS.md).)*
1. **Индекс хлорофилла:** $\text{NDCI} = (R_{705} - R_{665}) / (R_{705} + R_{665})$ — гасит колебания яркости солнца и общую дымку.
2. **Индекс мутности:** $\text{NDTI} = (R_{665} - R_{560}) / (R_{665} + R_{560})$ — отделяет глинистую взвесь от цветения.
3. **Оценка хлорофилла (Mishra & Mishra, 2012):** $\text{Chl-a}_{\text{est}} = \max(0{,}5;\; 14{,}039 + 86{,}115 \cdot \text{NDCI} + 194{,}325 \cdot \text{NDCI}^2)$.
4. **Индекс трофности Карлсона:** $\text{TSI} = 9{,}81 \cdot \ln(C_{\text{хл}}) + 30{,}6$.
5. **Сезонные координаты:** $\sin(2\pi d / 365{,}25)$ и $\cos(2\pi d / 365{,}25)$.

## ЧАСТЬ 2. Машинное обучение и два режима прогноза (`src/models/`)

**Откуда берёт данные:** читает `features_satellite.parquet`, `features_lab.parquet` и `dataset_passport.json` из Части 1.

### Что делает внутри:
1. **Честное разделение по времени (без перемешивания):**
   - обучение на ранних годах (`2018–2024`), проверка на самых свежих годах (`2025–2026`), чтобы модель никогда не знала будущее при обучении.
2. **Спутниковый режим (`train_satellite_models.py`):**
   - **Базовые модели для честного сравнения:** инерционный прогноз (*«через 10 дней будет как сегодня»*), линейная гребневая регрессия (`Ridge`), логистическая регрессия (`LogisticRegression`).
   - **Основные модели (градиентный бустинг `LightGBM`):**
     - регрессия оптических индексов (`target_ndci_next_10d`, `target_b04_b02_next_10d`) и оценки `target_chl_a_est_next_10d` на `+10 дней`;
     - бинарная классификация вероятности внимания ($\ge 15$ мкг/л) и опасного цветения ($\ge 25$ мкг/л) с балансировкой классов (чтобы не пропустить редкие вспышки).
3. **Лабораторный режим (`train_lab_models.py`):**
   - работает на `features_lab.parquet` для тех озёр, по которым загружены реальные лабораторные пробы (Нарочь, Мястро, Баторино);
   - решает две задачи:
     1) строит прогноз реального лабораторного хлорофилла-а по погоде + свойствам озера + прошлым замерам;
     2) строит **собственный 6-канальный оптико-лабораторный переводчик на мировом эталоне GLORIA** (`5 405` чистых пар после QC-фильтрации, из них `3 368` озёрных — `B02, B03, B04, B05, B06, B08 + отношения B04/B02, B03/B02, NDCI, NDTI → Chl-a в мкг/л`) и **проверяет его против формулы Mishra (2012) на 36 реальных лабораторных пробах БГУ за 2018–2019 гг.** по озёрам Нарочь, Мястро и Баторино!

### Что выдаёт на выходе:
- сериализованные модели в `src/models/saved_models/*.joblib`:
  - `optical_gloria_translator.joblib` — переводчик «спектр Sentinel-2 $\rightarrow$ хлорофилл-а (мкг/л)», обученный на GLORIA;
  - модели 10-дневного прогноза (спутниковый и лабораторный режимы);
- отчёт проверки `data/processed/model_metrics.json` (ошибки `RMSE`, `MAE`, `R²` для регрессии; `Precision`, `Recall`, `F1`, `ROC-AUC` для классификации; сравнение точности Mishra 2012 vs GLORIA-ML на реальных пробах БГУ 2018–2019; рейтинг важности признаков).

## ЧАСТЬ 3. Семантическая база знаний и машина логического вывода (`src/knowledge_graph/`)

**Откуда берёт данные:**
- паспорта и пороги озёр из `configs/water_bodies.yaml` и `data/reference/lakes.geojson` (включая `ecological_context`: режим ООПТ, каскад озёр, стратификация);
- числовой прогноз от Части 2 (концентрация хлорофилла с интервалом неопределённости `±MAE` и вероятность цветения — в выбранном пользователем режиме «Спутник» или «Лаборатория»);
- погодный контекст за последние 7–14 дней из Части 1 (`temp_mean_14d`, `calm_fraction_7d`).

### Что делает внутри:
1. Загружает формальную онтологию качества вод `ontology.ttl` (стандарт `W3C SOSA/SSN`, пространство имён `bywater:`) и проверяет структурную целостность через `SHACL` (`pyshacl`).
2. По прогнозной концентрации вычисляет **индекс Карлсона (`TSI`)** и определяет трофический класс (*Олиготрофный / Мезотрофный / Эвтрофный / Гиперэвтрофный*).
3. Прогоняет числа и погоду через **продукционные правила (СанПиН РБ + ООПТ-ограничения Нацпарка «Нарочанский»)**:
   - **`RED` (Опасность):** прогноз $\ge 25{,}0$ мкг/л или вероятность цветения $\ge 50\%$;
   - **`YELLOW` (Внимание):** прогноз $15{,}0\text{–}25{,}0$ мкг/л или сочетание жары ($T_{14} \ge 20~^{\circ}\text{C}$) и штиля ($\ge 30\%$ дней);
   - **`GREEN` (Норма):** все показатели безопасны.
4. Генерирует **понятные текстовые причины** (почему выставлен этот уровень) и **список разрешённых регламентных мер** (отбор проб на цианотоксины, уведомление Минприроды, ограничение купания, запрет химобработки на территории ООПТ).
5. Записывает новую оценку и предупреждение как **связанные факты в RDF-граф** (по которому работают аналитические запросы `SPARQL`).

### Что выдаёт на выходе:
- структурированный объект вердикта `AlertVerdict` для передачи в сервер;
- обновляемый файл графа фактов `data/processed/knowledge_graph_snapshot.ttl`.

## ЧАСТЬ 4. Сервер API и интерактивная веб-ГИС (`src/api/`, `frontend/`)

**Откуда берёт данные:** объединяет выходы Частей 1, 2 и 3.

### Что делает сервер (`FastAPI` + `Pydantic` + `Uvicorn`):
- `GET /lakes` — отдаёт список озёр, паспорта и геометрию `lakes.geojson` для карты;
- `GET /predict/{lake_id}?date=...&mode=satellite|lab` — запускает прогноз в выбранном режиме (**Спутник** или **Лаборатория**), прогоняет через Базу знаний и возвращает проверенный JSON (`AlertResponse`);
- `GET /history/{lake_id}?mode=satellite|lab` — отдаёт реальные временные ряды для графика;
- `GET /metrics` — отдаёт метрики точности моделей, сравнение GLORIA vs Mishra 2012 и отчёт качества данных;
- `POST /lab/upload` *(интерактивность)* — позволяет загрузить новую лабораторную пробу и сразу сравнить её с прогнозом спутника.

### Как выглядит сайт для пользователя (ориентир — интерфейс проекта `ИГИСИТ`):
- **Интерактивная карта озёр** с точными контурами из `lakes.geojson` (окрашены по текущему уровню риска: зелёный / жёлтый / красный).
- **Клик по любому озеру** открывает боковую карточку: паспорт озера, прогноз на +10 дней с коридором `±MAE`, индекс Карлсона, человеческие причины и советы из Базы знаний.
- **Переключатель режима «Спутник / Лаборатория»** (для озёр с лабораторными данными — наглядное сравнение прогноза по спутнику и по лабораторным анализам).
- **График реальных рядов 2018–2026 гг.** с линией санитарного порога `25 мкг/л`, реальными датами снимков и точками лабораторных проб БГУ.
