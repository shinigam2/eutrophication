# Соглашение о форматах данных между 4 частями проекта

Этот документ — **единая договорённость для всех 4 участников команды**. В нём простым языком описано, **какие именно файлы создаёт Часть 1** (сбор и подготовка данных), **что означает каждый столбец в таблицах**, в чём он измеряется и **как им пользуются Части 2, 3 и 4**.

Пока все участники придерживаются этих имён файлов и столбцов, каждый может писать свою часть проекта независимо — и в конце всё состыкуется без поломок.

## 1. Справочник озёр и их контуры на карте

### Файл `configs/water_bodies.yaml`
Обычный текстовый файл настроек, где перечислены все озёра проекта. Чтобы добавить новое озеро (например, прямо на опроцентовке перед преподавателем), достаточно дописать сюда один блок — менять Python-код не нужно.

Что хранится по каждому озеру:
- **Идентификатор (`id`)** — короткий латинский код без пробелов, связывает все таблицы между собой (например, `naroch`, `myastro`, `batorino`, `myadel`).
- **Названия (`name_ru`, `name_be`)** — название озера на русском и белорусском языках для отображения на сайте и в отчётах.
- **Ссылка на контур на карте (`osm_type`, `osm_id`)** — номер объекта в OpenStreetMap, по которому программа сама скачивает точную береговую линию озера.
- **Координаты центра (`center_lat`, `center_lon`)** — широта и долгота середины озера (для загрузки погоды и центрирования карты).
- **Размеры и глубина (морфометрия):**
  - `area_km2` — площадь водной поверхности (км²);
  - `mean_depth_m` — средняя глубина озера (м);
  - `max_depth_m` — максимальная глубина (м);
  - `volume_mln_m3` — объём воды (млн м³);
  - `watershed_km2` — площадь водосбора, то есть земли вокруг озера, с которой дожди стекают в него (км²).
- **Пороговые значения тревоги:** уровень внимания (`15,0` мкг/л) и опасного цветения (`25,0` мкг/л).

### Файл `data/reference/lakes.geojson`
Стандартный картографический файл с **точными многоугольниками береговых линий** всех озёр (скачан из OpenStreetMap).
- **Часть 1** использует его, чтобы вырезать со спутниковых снимков строго воду внутри озера (отступая от камышей и берега).
- **Часть 4** загружает этот же файл прямо на веб-карту, чтобы можно было кликать мышкой по любому озеру.

### 2.3. Сводка спутника по 10-дневным периодам (декадам) — `satellite_decadal.parquet`
Поскольку спутник летает неравномерно (то через 3 дня, то через 8 из-за облаков), мы приводим все снимки к **ровной сетке с шагом 10 дней** (1-е, 11-е, 21-е число каждого месяца — берём медиану снимков за 10-дневное окно).
К каждой строке добавляются два честных поля качества:
- `obs_status` — статус наблюдения:
  - `valid` — есть реальный чистый снимок со спутника;
  - `interpolated_1step` — была одна пасмурная декада между двумя чистыми, значение аккуратно восстановлено по соседям;
  - `cloudy_missing` — облачность держалась 2+ декады подряд, данных честно нет (`NaN`);
  - `ice_cover` — зима / лёд на озере, вода не видна (`NaN`).
- `scenes_in_decade` — сколько реальных снимков вошло в расчёт этой декады (`0, 1, 2, 3...`).

| `chl_a_lab_ug_l` | Лабораторная концентрация хлорофилла-а | мкг/л | `3,8` |
| `secchi_depth_m` | Прозрачность воды по белому диску Секки *(если есть)* | м | `5,4` |

### 2.5. Отчёт о качестве данных — `data_quality_report.json`
Автоматическая справка, которая генерируется при каждом запуске Части 1: сколько дней погоды загружено, сколько реальных сцен Sentinel-2 прошло проверку, сколько снимков отброшено из-за облаков, какой процент пропусков по каждому озеру и какие озёра прошли/не прошли отбор по пикселям.

## 3. Главная витрина признаков для машинного обучения — папка `data/processed/`

### Основная витрина (Спутниковый режим): `features_satellite.parquet`
*(и её копия `features_satellite.csv`, чтобы любой участник мог открыть и посмотреть глазами в Excel)*

Каждая строка отвечает на вопрос: **«Что мы знали об озере и погоде на дату `date`, и что случилось с водой ровно через 10 дней?»**

Уникальный ключ строки: пара **`(water_body_id, date)`**. Все столбцы разделены на 4 понятные группы:

#### Группа А. Служебная информация (не подаётся в модель как признак)
| Столбец | Что означает | Пример |
| :--- | :--- | :---: |
| `water_body_id` | Код озера | `batorino` |
| `water_body_name` | Русское название озера | `Озеро Баторино` |
| `date` | Дата среза (декада) | `2026-07-11` |
| `obs_status` | Как получено наблюдение (`valid` / `interpolated_1step`) | `valid` |
| `valid_water_pixels` | Число чистых пикселей воды на снимке | `11 820` |
| `scenes_in_decade` | Количество реальных снимков в этой декаде | `2` |

#### Группа Б. Входные признаки (то, на основе чего модель делает прогноз — строго на дату `date` и в прошлом!)
| Подгруппа | Столбец | Понятное значение и физический смысл | Единица |
| :--- | :--- | :--- | :---: |
| **Сезонность** | `month` | Номер месяца (4..10) | `1..12` |
| | `day_of_year` | Порядковый день года (1..366) | сут |
| | `sin_doy`, `cos_doy` | «Круговые» координаты дня года (чтобы конец и начало года плавно стыковались) | `−1..+1` |
| **Свойства озера** | `area_km2` | Площадь зеркала озера | км² |
| | `mean_depth_m` | Средняя глубина (мелкие прогреваются и цветут быстрее) | м |
| | `max_depth_m` | Максимальная глубина (глубокие удерживают биогены у дна) | м |
| | `watershed_ratio` | Во сколько раз площадь водосбора больше самого озера (чем больше, тем больше смыв с полей) | безразм. |
| **Состояние воды сейчас и 10 дней назад** | `ndci_current` | Реальный спутниковый индекс хлорофилла сейчас | `−1..+1` |
| | `ndci_lag10d` | Реальный индекс хлорофилла 10 дней назад | `−1..+1` |
| | `ndci_growth_10d` | Насколько вырос/упал индекс за последние 10 дней (`сейчас − 10 дней назад`) | `−2..+2` |
| | `ndti_current` | Текущий индекс мутности воды | `−1..+1` |
| | `chl_a_est_current` | Текущая спутниковая оценка хлорофилла-а | мкг/л |
| | `chl_a_est_lag10d` | Спутниковая оценка хлорофилла-а 10 дней назад | мкг/л |
| | `tsi_current` | Текущий индекс трофности Карлсона | баллы |
| **Накопленная погода (строго ДО даты `date`)** | `temp_mean_7d`, `temp_mean_14d`, `temp_mean_21d` | Средняя температура воздуха за последние 7, 14 и 21 день (прогрев воды) | °C |
| | `temp_max_7d` | Самая высокая температура за последние 7 дней (пик жары) | °C |
| | `hot_days_14d` | Сколько дней за последние 2 недели было жарче `22 °C` | дней |
| | `precip_sum_7d`, `precip_sum_14d` | Сумма дождей за 7 и 14 дней (смыв удобрений с берегов в воду) | мм |
| | `radiation_mean_7d` | Средняя солнечная энергия за 7 дней (свет для фотосинтеза водорослей) | МДж/м² |
| | `wind_mean_7d` | Средняя скорость ветра за 7 дней (ветер перемешивает воду и мешает цветению) | м/с |
| | `calm_fraction_7d` | Доля тихих (штилевых) дней за 7 дней, когда ветер `< 2,2 м/с` (в штиль цианобактерии всплывают плёнкой наверх) | `0..1` |

#### Группа В. Целевые переменные (то, что модель должна предсказать на `+10 дней` вперёд)
| Столбец | Что означает | Единица | Для какой модели (Часть 2) |
| :--- | :--- | :---: | :--- |
| `target_ndci_next_10d` | Реальный индекс `NDCI` на следующей декаде (`+10 дней`) | `−1..+1` | Регрессия по чистому спутниковому индексу |
| `target_chl_a_est_next_10d` | Оценка хлорофилла-а через 10 дней | мкг/л | Регрессия концентрации хлорофилла-а |
| `target_attention_risk_next_10d` | Флаг уровня внимания через 10 дней (`1`, если `≥ 15,0` мкг/л, иначе `0`) | `0` или `1` | Классификатор раннего риска (снимает дисбаланс редких вспышек `≥ 25`) |
| `target_bloom_risk_next_10d` | Флаг опасного цветения через 10 дней (`1`, если `≥ 25,0` мкг/л, иначе `0`) | `0` или `1` | Классификатор вероятности опасного цветения |

### Вторая витрина (Лабораторный режим): `features_lab.parquet`
Строится **для тех озёр, по которым загружены реальные лабораторные пробы** в `data/lab/lab_measurements.csv` (в первую очередь Нарочь, Мястро и Баторино).
Содержит те же самые погодные окна (7/14/21 день), свойства озера, сезонность и ближайшие спутниковые индексы, но в качестве целевых и опорных значений использует **реальный лабораторный хлорофилл-а из пробирки (`chl_a_lab_ug_l`)**.

### Паспорт витрины: `dataset_passport.json`
Короткий JSON-файл, который автоматически создаётся вместе с витринами и содержит точные списки колонок (какие — служебные, какие — признаки, какие — цели), диапазон дат, число строк и список включённых озёр. Участнику 2 не нужно вручную копировать списки столбцов — он просто читает их из этого файла.

### Согласованные дополнения для Частей 2, 3 и 4 (по сверке с ТЗ преподавателя)
- **Часть 2 → Часть 4 (неопределённость прогноза):** вместе с точечным прогнозом на `+10 дней` модель отдаёт доверительный интервал (`pred_low_ug_l`, `pred_high_ug_l` по квантильной/кросс-валидационной ошибке `±MAE`) и статус свежести спутникового среза (`obs_status`).
- **Часть 3 (валидация графа знаний):** помимо онтологии `W3C SOSA/SSN` (`RDF/Turtle`), правил вывода и `SPARQL`, рекомендуется добавить компактный файл **`SHACL`** (`shapes.ttl` + `pyshacl`) для формальной проверки структуры графа перед выдачей вердикта.
